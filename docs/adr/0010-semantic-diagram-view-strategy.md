# ADR-0010：每层按语义选择图型，共用一套知识图事实源

- 状态：Accepted
- 日期：2026-07-25

## 背景

不同层级要回答的问题不同。系统边界与部署关系适合软件架构图，数据经过哪些处理与存储适合数据流图，跨组件调用时序适合序列图，线程和锁的状态转换适合状态机。把所有内容都压成从左到右的同一种链路，会浪费画布空间，也会削弱并行、回路、作用域和时序信息。

## 决策

知识页继续以结构化节点、边、解释、下钻和双向引用作为唯一事实源；`layout.diagramType` 明确本层首选图型，渲染器只负责表现：

| `diagramType` | 主要回答的问题 | 典型页面 |
|---|---|---|
| `SOFTWARE_ARCHITECTURE` | 组件、实例、容器和网络边界怎样协作 | HTTP 请求全景、服务器与 Docker |
| `LOGICAL_DATA_FLOW` | 业务数据经过哪些逻辑处理和存储 | 注册、登录、订单等业务流程 |
| `PHYSICAL_DATA_FLOW` | API、SQL、Topic 和响应怎样实际传输 | MySQL、缓存、消息队列链路 |
| `SEQUENCE` | 多参与者之间按时间发生了什么 | Spring MVC、RPC、事务调用 |
| `STATE_MACHINE` | 对象、线程或锁如何在状态间转换 | 线程生命周期、`synchronized` |
| `CALL_FLOW` | 方法、代理和运行时栈如何逐层调用 | AOP、JVM 调用栈、类加载 |
| `HYBRID` | 单一图型无法清楚表达的受控组合 | 架构边界内嵌一条关键时序 |

作者必须显式选择图型，系统可根据拓扑给出建议，但不能在发布时静默改型。所有渲染器共用以下交互语义：

- 节点选择、下钻、面包屑、来源返回和双向引用；
- 流程边、异常边、引用边的稳定视觉区分；
- 多实例、多线程、队列和连接池的 `Multiplicity` 数量表达；
- 与节点对应的解释面板、步骤编号和键盘可达性；
- 至少一条从入口到出口的完整可验证主链路。

普通阅读默认充分利用当前视口。线性链路使用 `FIT_VIEWPORT` 折行；复杂架构或物理数据流可使用 `FREE_CANVAS`，但首次进入必须自动适配整图，不能要求用户先横向拖动才能找到入口或出口。

## 选择理由

- 图型跟随问题，而不是让知识迁就单一组件；
- 同一事实源可以被不同渲染器、搜索、校验和未来 AI 解释共同消费；
- 参考工程白板的空间组织，同时保留可审查、可版本化的数据语义；
- 新业务场景只需组合内容与图型，不必复制整套页面逻辑。

## 备选

### 所有页面都使用自由白板

表达最自由，但坐标和图形会成为事实源，难以校验完整链路、稳定下钻和无障碍阅读，因此不采用。

### 所有页面都使用同一种流程图

实现和学习成本最低，但无法清楚表达作用域、并行实例、时间轴和状态转换，仅保留为 M0 线性内容的过渡方案。

### 每种图型维护独立数据模型

可完全贴合各图型，但同一节点和边会重复建模，双链、搜索、审核和迁移成本过高，因此不采用。

### 系统自动推断图型

作者负担最低，但相同拓扑可能服务不同教学目标；自动推断只作为编辑建议，不作为发布决策。

## 取舍

多渲染器会增加布局算法、响应式、回归测试和无障碍实现成本。M0 先实现 `SOFTWARE_ARCHITECTURE`、`SEQUENCE`、`LOGICAL_DATA_FLOW` 三种可交互样板，M1 再将布局参数完全数据化；其余类型在 Schema 中稳定占位。任一未实现类型必须回退到通用有向图，并明确标记“通用视图”，不能渲染空白页。

`HYBRID` 只允许一个主图型加一个局部辅图，禁止无限嵌套，避免再次形成难以阅读的白板。

## 异常与补偿

- 图型值非法：Schema 阻断发布；
- 指定渲染器未加载：回退通用有向图并上报指标，不丢失内容；
- 自动布局超时：使用已保存坐标；无坐标时回退简化分层布局；
- 画布超出视口：首次自动适配整图，并提供放大、缩小和重置；
- 节点或边无法进入完整主链路：语义校验阻断发布；
- 小屏无法保持原图型可读：切换为同语义的纵向阅读模式，不截断节点和解释。

## 监控指标

- `diagram_render_duration_ms{diagramType}`：P95 小于 800 ms；
- `diagram_renderer_fallback_total{diagramType,reason}`：正式内容目标为 0；
- `fit_viewport_overflow_total{viewport,diagramType}`：默认视图横向溢出目标为 0；
- `path_completion_rate{diagramType}`：用户能从入口走到出口的比例不低于 80%；
- `drill_success_rate{diagramType}`：3 分钟内完成至少 3 层下钻的比例不低于 80%。

## 验收

- HTTP 请求全景以软件架构图表达边界、组件和多实例；
- 至少一个 Spring/RPC 页面以序列图表达参与者与请求/响应；
- 至少一个业务场景同时提供逻辑与物理数据流视角；
- `synchronized` 页面以状态机或调用流程清楚表达竞争、持有与释放；
- 每种已实现图型都保留下钻、双链、解释和数量语义；
- 1440×900、1180×800、390×844 首次进入均能定位入口、出口和当前层说明。

## 复审触发

出现需要 BPMN、ER 图、火焰图或实时拓扑的明确场景，或任一图型连续 5 个页面依赖大量 `HYBRID` 特例时复审。
