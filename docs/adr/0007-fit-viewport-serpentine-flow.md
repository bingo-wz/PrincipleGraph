# ADR-0007：主链路默认适配视口并蛇形折行

- 状态：Accepted
- 日期：2026-07-25

## 背景

8–20 个节点排成单行时，用户需要频繁横向拖动画布，入口、出口和已读上下文无法同时出现在视野内。主链路的逻辑方向需要保持，但不应等同于无限横向页面。

## 决策

内容模型继续保存有向边和 `RIGHT` 逻辑方向。浏览态默认使用 `FIT_VIEWPORT`：

- 桌面按最多 4 列、窄屏按 2 列蛇形折行；
- 奇数行从左向右，偶数行从右向左；
- 折返点显示垂直箭头、步骤序号和边标签；
- 默认隐藏横向滚动，仅在用户主动放大或进入自由画布时允许横向平移；
- 分支说明使用自适应网格，占用画布剩余宽度。

## 选择理由

- 在一个视口内保留更多上下文，降低寻找下一节点的操作成本；
- 不修改边顺序，内容、搜索和双链仍使用同一稳定节点 ID；
- 规则布局可预测，适合 M0 的 8–10 节点页面；
- 后续可将同一 `FIT_VIEWPORT` 规则接到 React Flow/ELK 的展示层。

## 备选

- 单行无限横向画布：实现简单、方向最直观，但需要持续横向拖动；
- 完全纵向时间线：小屏友好，但宽屏利用率低，系统拓扑感弱；
- 力导向布局：空间利用率高，但执行顺序不稳定；
- 缩小整条链路直到一屏容纳：无需折行，但节点文字会低于可读尺寸。

## 取舍

折返点比单行多一次视线转向，边标签也需要专门布局。作为补偿，转折必须使用明显的垂直箭头和连续序号。自由布局仍保留为作者模式或复杂拓扑的备选，不能成为普通阅读的默认模式。

## 验收

- 默认 1440×900、1180×800 和 390×844 视口不因主链路产生横向滚动；
- 用户可沿序号从入口走到出口，不把折返点当成分支；
- 主链路节点可读字号不低于现有 M0 基线；
- 主动放大后允许平移，但重置“适配整页”必须恢复无横向滚动状态。

## 复审触发

出现单页超过 20 个主节点、复合并行链路超过 3 条，或 5 人测试中超过 1 人无法理解折返方向时复审。
