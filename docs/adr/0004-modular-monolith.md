# ADR-0004：后端采用模块化单体

- 状态：Accepted
- 日期：2026-07-25

## 背景

查询、校验、版本和发布在 MVP 阶段共享事务边界，团队规模不足以承担多个服务的部署成本。

## 决策

使用 Spring Boot 模块化单体，模块包括 `catalog`、`content`、`validation`、`publication`、`query`、`search`、`identity` 和 `audit`。ArchUnit 阻止跨模块 Repository 访问。

## 备选

- 从第一天拆微服务：独立扩展但增加网络、部署和一致性成本；
- Node.js 单体：语言统一但不能提升当前产品验证效率；
- 纯静态站点：上线快但版本与双链能力不足。

## 后果

- 发布快照可在一个数据库事务中切换；
- 代码边界需要测试约束，不能只靠目录命名；
- 将来只能在有量化收益时通过领域事件拆分。

## 复审触发

出现独立团队所有权、独立扩缩容或单模块资源争用证据时复审。
