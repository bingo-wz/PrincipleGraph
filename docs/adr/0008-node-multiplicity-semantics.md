# ADR-0008：节点数量作为一等内容语义

- 状态：Accepted
- 日期：2026-07-25

## 背景

“Java 服务实例”“Executor 工作线程”“连接池”等节点只画一个图标时，会把多实例、多线程系统误读成单体结构；直接复制多个完整节点又会让同一条请求看起来同时经过所有副本。

## 决策

节点可选携带 `Multiplicity`：

- `EXACT`：当前场景中的确定数量，例如同一 monitor 同时只有 1 个持有线程；
- `EXAMPLE`：为了教学而选定的示意数量；
- `DYNAMIC`：运行时或部署时变化的 `N/T/C/K/Q`；
- `value` 与 `unit` 组成数量标签；
- `visualCount` 只控制 1–6 个重复小图标；
- `selectedCount` 高亮当前请求实际命中的实例、线程或连接；
- `note` 必须解释示意图标、真实数量和当前链路之间的关系。

重复小图标属于节点内部视觉，不生成新的流程节点、稳定 ID 或流程边。

## 选择理由

- 同时表达“系统里有多个”和“这次请求只走其中一个”；
- 数量语义进入 Schema 后可被校验、搜索、审核和后续监控数据覆盖；
- 避免把三枚示意图标硬编码成“真实副本数为 3”；
- 同一个模型可以覆盖服务副本、线程池、队列、连接池和锁竞争。

## 备选

- 复制完整节点：拓扑最直观，但会放大图规模并混淆单请求路径；
- 只显示 `×N` 文本：实现最轻，但缺少视觉上的并行和数量差异；
- 直接接入实时监控数量：信息最真实，但引入数据源、时效、权限和历史回放问题；
- 每类节点自定义字段：短期灵活，长期无法统一校验和渲染。

## 取舍

内部重复图标不能单独点击，也不能表示独立故障域。MVP 优先教学语义，实时数量留到业务场景演进；接入实时数据后仍必须显示数据时间和来源，不能静默替换教学假设。

## 校验与异常

- `selectedCount > visualCount` 阻断发布；
- 缺少 `mode/value/unit/visualCount/note` 时 Schema 拒绝；
- 动态数量无法取得实时值时显示符号值，不回退为错误的固定数字；
- 实时数据陈旧时保留内容值并标记数据时间，不删除节点。

## 验收

- 首层 Java 服务显示动态 `N` 与至少 3 个示意实例，其中 1 个高亮；
- Spring/JVM 线程节点显示动态 `T` 与当前请求占用的 1 个 Worker；
- synchronized 页区分 `K` 个竞争线程与 1 个持有线程；
- 5 人测试中至少 4 人能说明图标数是示意、字母是动态数量、高亮是当前落点。

## 复审触发

业务场景需要逐实例健康状态、真实拓扑连线或历史容量回放时，评估将 `Multiplicity` 升级为独立实例集合。
