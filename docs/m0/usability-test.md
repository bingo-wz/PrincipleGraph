# M0：5 人可用性测试脚本

## 1. 招募条件

共 5 人：

- 2 名 1–3 年 Java 工程师；
- 2 名 3–7 年 Java 工程师；
- 1 名近期参与过 Java 技术面试的面试官或候选人。

排除：参与 PrincipleGraph 设计的人。

## 2. 测试准备

- 单人 30 分钟，远程共享屏幕或现场观察；
- 首次打开原型前不解释视觉规则；
- 受试者使用自己的语言思考出声；
- 记录任务完成、首次误点、犹豫时间和原话，不在任务中教学。

## 3. 开场白

“这不是对你的技术能力测试，而是在测试产品是否说得清楚。请一边操作一边说出你认为界面表达了什么。如果卡住，请继续说出你原本期望看到什么。”

## 4. 任务

### T1：找到一次请求的总入口

指令：“请找出一个外部 HTTP 请求从哪里开始、最终回到哪里。”

成功：

- 20 秒内指出浏览器入口和浏览器响应出口；
- 能按顺序说出至少 5 个中间组件。

### T2：进入服务器内部

指令：“请求已经被选到一台服务器，请继续找到它进入 Docker 容器和 Java 进程的过程。”

成功：

- 使用显式下钻进入 `server-container-path`；
- 能指出 bridge、veth/network namespace、容器端口和 JVM socket；
- 没有把相关引用当成流程边。

### T3：进入 Spring MVC

指令：“现在继续找到 Spring MVC 如何调用 Controller。”

成功：

- 进入 `spring-web-request-chain`；
- 指出 FilterChain 在 DispatcherServlet 之前；
- 说出 HandlerMapping 和 HandlerAdapter 的不同职责。

### T4：从事务跳到 MySQL，再返回来源

指令：“查看声明式事务中的数据库操作，再进入 MySQL 索引原理，最后回到刚才的事务页面。”

成功：

- 使用下钻或相关引用打开 MySQL 页；
- 能使用“返回来源”或面包屑返回；
- 明白回表只发生在当前设定的非覆盖二级索引查询。

### T5：搜索 synchronized 并解释关联

指令：“不从头下钻，直接找到 synchronized，并说明它为什么与 JVM 线程执行有关。”

成功：

- 搜索并打开目标页；
- 正确识别 monitor 获取、临界区、释放和 happens-before；
- 通过双向引用回到 JVM 线程页。

## 5. 观察记录

| 字段 | 说明 |
|---|---|
| `participantId` | P01–P05，不记录真实姓名 |
| `experienceBand` | 1–3 / 3–7 / interviewer |
| `taskId` | T1–T5 |
| `completed` | true/false |
| `timeToCompleteSec` | 完成时间 |
| `firstWrongAction` | 首次错误动作 |
| `hesitationSec` | 连续无动作时间 |
| `flowVsDrillCorrect` | 是否区分流程与下钻 |
| `quote` | 最有解释力的一句原话 |
| `severity` | blocker / major / minor |

## 6. 判定门槛

- T1–T4 每项至少 4/5 人独立完成；
- T5 至少 3/5 人完成；
- 至少 4/5 人正确区分流程边、下钻和相关引用；
- 主链路复述正确率 ≥80%；
- 任一 blocker 必须修改原型后复测；
- 不以“用户技术知识不足”解释反复出现的界面误解。

## 7. 访谈问题

任务完成后再问：

1. 你会更常从业务场景还是搜索进入？
2. 哪一页信息最多但仍能看懂？哪一页已经过载？
3. 右侧说明和画布内注释，你希望默认看到哪一个？
4. 哪个节点你最想继续下钻但当前没有？
5. 如果用它准备面试，你会在什么时刻打开它？
